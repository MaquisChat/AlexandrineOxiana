## NEEDS A RULING

**FR-170 (b): older batches have no created ids, so their folder-name flags (R64) are not shown.** `ReviewQueue.tsx` `madeByBatch` returns false when the batch has no `created` (a batch recorded before R118) or is not found: the R64 warning fails open for pseudonymised projects. 41b1 M7 asked to fail closed. But the current flag sentence asserts "These collection names come from folder names…", which would be untrue for a collection that existed before such a batch. Options: (1) leave it (fail open, as today); (2) fail closed with the existing sentence (may claim a false origin); (3) fail closed with a hedged sentence for a folder/zip/device batch without `created` (or an unknown batch) — recommended: "This import was recorded before the app kept which collections it made, so these collection names may come from folder names, which can carry participants' names. Check them, and rename the collection or move the item if one names someone." (and the same for tags: "… so these tag names may come from folder names … rename or remove a tag that names someone."). A screen-only change in `ReviewQueue.tsx`, size S once the wording is ruled.

**FR-413: the watched-folders warning can go stale.** The finding's path is gone: `DELETE /projects/:id/watched-folders/:wid` no longer calls `startWatches`; `startWatches` runs only when the library opens (`state.ts:892`). Since the watched-folders rework, a folder is started on its own (add, `retry`, move folder: `routes/watched-folders.ts`), so after an unreadable list at open, a folder added or retried later runs while the library-wide session warning still says "its watched folders are not running now" — partly stale, and partly still true (the others did not start). This needs a choice of behaviour, in the service (`apps/library-service`, outside this batch's screens): (1) when a later read of the list succeeds, restart every project's watches and clear the warning (the warning then always tells the truth; costs a restart path); (2) keep the warning but make it a statement about the open, always true — recommended as the small fix: "This computer's list of watched folders could not be read when this library was opened, so its watched folders were not started then: files put in them are not imported until they run. Open the library again to start them all." (StatusBanner.tsx `WARNINGS["watched-folders-unreadable"]`); (3) (1) plus moving it out of `GET /libraries/integrity` (the review's "category mix"). My recommendation: (2) now, (1) if the owner wants the warning to clear itself.
