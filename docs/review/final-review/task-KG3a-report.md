## NEEDS A RULING

- **FR-718, the limit's value.** The brief says to use "the limit the service uses for its other password-store or settings writes", but there is none: every other settings write (`updateAppSettingStrict` in appearance, fonts, find-screen, search settings) and every keyring write (`setSecret`) is unbounded. I built the mechanism with **30 s** (`PAIRING_SAVE_LIMIT_MS`), below the screen's own 60 s wait (`SAVING_SLOW_MS`). With that value the screen shows the not-saved outcome rather than "taking longer". As a result, the screen's "The pairing is taking longer than it should…" can now appear only when the screen's own status reads fall behind. Options: (a) keep 30 s (my recommendation); (b) 60 s, the same as the screen, in which case the screen may briefly say "taking longer… paired once it appears in the list" just before the service gives up; (c) another value. Only the constant changes in each case.
