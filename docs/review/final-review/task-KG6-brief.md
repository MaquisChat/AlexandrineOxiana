## FR-734, point 1 — two builds of the sign-in window can overlap (R503 i)
`apps/desktop/src-tauri/src/library_window.rs` (and `open_library_window`/`close_library_window` in `lib.rs`): the sign-in window is where a researcher signs in to their library's website; a ticket names the open that owns it (FR-561, Rulings R472, R489, R491 B — read them; read the review `/home/user/AlexandrineOxiana/.superpowers/sdd/PLAN/task-RE7d-review.md` part A and the report `task-RE7h-report.md`/`task-RE7i-report.md` if present, searching "overlap"). The residue: two BUILDS of the window can overlap (the second open starts while the first's window is still being built); the shell then loses track of the first window, and closing it ends the newer request. Ruled: the shell builds one sign-in window at a time — a second open that arrives while a build is in flight either waits for it to finish and then takes over by the existing ticket rule, or overtakes it so that the first build's window, when it appears, is closed and never owned by nobody; never two windows, never a window nobody owns, never a newer window closed by something older, no lock held across an await or a call back into the host (the existing tests' rules). Decide which by reading what the existing ownership code makes smallest. Tests first, beside the existing `library_window::tests` (they model opens, closes and late answers without a real window: extend the model to a build in flight), each failing without the guard.
