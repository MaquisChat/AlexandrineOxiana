## The fault and the ruling
`copyFileAtomic` (`packages/library/src/fs/atomic.ts`) is the one function through which the product copies a file into place: imports, exports, a library's move, proxies, the media worker's inputs and outputs, a transaction's copies. It made its source stream first (with `decode` already piped into the decrypt stream, so already flowing), then awaited the temp file's `chmod`, and only then attached error listeners. A source that failed during that wait (an encrypted project locked mid-read; a file under another key; a damaged file; a missing file) emitted an error nobody listened for — an uncaught exception, which ends the local service (one Node process, no last handler) — and the copy then waited for ever. Found on GitHub's CI as a 30-minute hang of one row of `packages/library/src/repo/lock-mid-read.test.ts`.
