## What the failing item is
The "sign-in window" (`apps/desktop/src-tauri/src/library_window.rs`; Find and acquire's "Get through my library") is a second window in which a researcher signs in to their library's website; pages in it are OUTSIDE pages and must be able to call nothing of the app. The launch check proves that with a probe, `apps/desktop/src-tauri/src/library_probe.js` (compiled into debug builds only; given to the sign-in window as an initialization script only in test mode with `AO_SHELL_LIBRARY_PROBE` set — `library_window.rs` about :2026 and the `library_probe` module about :2113–2160; `src/probe.rs` :18 for the main window's part, which asks the shell to open the sign-in window at the probe's `open_address`). The probe runs in the window's main frame, tries every command, and REPORTS BY NAVIGATING the window to `http://127.0.0.1:<port>/report?r=<json>` — a small HTTP server the launch check runs (`launch-check.mjs`: `startReportServer` about :796–830, `/page` is the outside page the window is opened at, `/report` the report; `libraryReportFrom` :185; `libraryProbeProblems` :167; the wait about :1015). "The sign-in window's probe reported nothing" means that server never got a `/report` request.

`Info.plist` already sets `NSAppTransportSecurity` → `NSAllowsLocalNetworking` (the main window talks to the service over http on 127.0.0.1, and that works on the Mac: "the page reached the service").
