## Point 1 (I5) — Move library never says "Nothing was copied or changed" without asking the service
Moving a library copies every file to a new place; the service (`apps/library-service/src/routes/libraries.ts` about :185–202) marks the move as running, waits up to 60 s for changes in progress, and only then sends its first bytes — and it runs the move to its end whatever the client does. If the connection drops in that window, the screen (`MoveLibrary.tsx` about :129–137) gets a status-0 failure before any answer, and says "The move could not be started: … Nothing was copied or changed." and goes back to the plan — while the move may be running. (The ledger's old point: "do not claim 'nothing changed'; poll move/status instead".)
**Build:** after ANY failure of the move request that is not a plain refusal from the service (a status-0 / network failure, a cut-off stream, a time-out — whether or not the first bytes had arrived), the screen asks the service what is true (`/libraries/move/status`, which the cut-off path `pickUp` already uses — read it) BEFORE it says anything, and goes on asking at the interval `pickUp` uses until the service answers: a move is running → the screen shows the move in progress and follows it exactly as the cut-off path does; a move finished → its result; no move is running and none was made → only then "The move could not be started: … Nothing was copied or changed."; the service cannot be reached at all → a sentence that does NOT claim anything about the files, exactly: "The connection to the app's service was lost. The move may still be running. This screen will show what happened as soon as the service answers." (and it keeps asking). A plain refusal (4xx with a reason) is shown as now.
**Tests first:** the reviewer's probe (the move request throws `ApiClientError(0, UNAVAILABLE)`) → `moveStatus` IS asked, and the false sentence is not shown while the status says a move is running; each of the four outcomes above; the status request itself failing twice and then answering.
