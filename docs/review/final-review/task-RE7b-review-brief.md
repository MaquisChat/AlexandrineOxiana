The feature: "Find and acquire" keeps a queue of references and looks for a copy of each (open-access sources, the researcher's library sign-in). A source of the library may hold its file as a LINK to a file elsewhere on the computer (not a stored copy). When that linked file cannot be found (an unplugged drive, a moved file), Find and acquire used to rest the entry as "in your library" although there is nothing to read. Now: the entry says the linked file cannot be found and offers "Get a copy for this source"; only when the researcher presses it does the app look for a copy; a file it finds is HELD for the researcher's decision ("Use this file" / "Not this file"), and "Use this file" adds the copy BESIDE the link (the link is kept).

The project owner's two standing rules that this feature must never break (rulings R301 and R303; `grep -n -E "Ruling R301|Ruling R303" …LEDGER.md | cut -c1-3000`): **a found file is NEVER attached to a source without the researcher's confirmation — it goes into the queue for approval, one by one**; and nothing is fetched that the researcher did not ask for.
