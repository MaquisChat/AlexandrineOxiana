## The setting
When a library is opened, a change that a crash interrupted is undone. Usually completely. Sometimes not: a step failed; a file a person put or changed by hand is in the way (since KG-1b the undo leaves such a file exactly where it is and stays incomplete, with the cause and the path: `hand-changed-file` where the change's own file was changed, `path-occupied` where a file stands at the place of an original to be put back — the researcher moves the file away and the roll-back then completes); the copy the app kept of a trashed original is gone, so the original can NEVER be put back. While an undo is incomplete the project refuses every change (`RecoveryPendingError`), the change stays in the list of interrupted changes (the screen that lists them, with "Roll it back": find it — `pending-writes.ts` in the library, its route, its screen), a banner is shown (`packages/ui/src/components/StatusBanner.tsx`, the warning kinds and their sentences shared with the service), and the library's integrity warnings list it. Recovery's warnings are held in memory only.
