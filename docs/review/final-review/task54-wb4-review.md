### Important

**I1 — A reference export written over any file in the library: an original, `governance.yaml`, a source file.**
`export/refman-export.ts:378-391` (`writeRefmanExport`) writes `outputPath` with `writeFileAtomic` and checks nothing about where it is; the CLI (`apps/cli/src/commands/export.ts:18,28-37`, "--output <file> … replaced if it exists") and the service route (`apps/library-service/src/routes/citations.ts:79-91`, `outputPath`, only `isAbsolute`; `requireSession()`, so a read-only library too) pass it straight through. Probe: a source with a copied PDF original; `writeRefmanExport(repo, p, [sid], "bibtex", <the asset's absolute path>)` → no error; the original then begins `% Exported by Alexandrine Oxiana (UTF-8)\n@article{smithpape…`; the same call onto `<project>/governance.yaml` replaced the rules with RIS text. The change is not a governed library change (no store/delete decision on the overwritten file, no txn marker, audited only as `export.refman`), and an original is modified — two of the standing "never" rules. The open-format export refuses a destination inside the library (`project-export.ts:261-266`, R92 I1) and R362 c / R368 refuse imports from inside it; the reference export, its export-side twin, was left out. Direction: refuse an `outputPath` whose real path (nearest existing ancestor, as `realOrResolved`) lies inside the library, in the library function so CLI and service both get it; test with an original and the rules file.

**I2 — Reference exports and the open-format export's `sources.bib` / `sources.csl.json` bypass the participant rules of R88 (check 1, check 2).**
`refman-export.ts:279-295` (`refOf`) copies `s.creators`, `primary(s.title)`, the URL and (`:330`) `s.citationKey` verbatim; `bibliography.ts` alone applies `participantRules` + `toCslItem` (codes for participants, fail closed, scrubbed titles, no citation key when participants are involved — `csl-map.ts:320-377`). `project-export.ts:435-438` builds `sources.bib` and `sources.csl.json` with the refman writer. Probe (PSEUDO_GOV, encrypted, an identifiable social post by `@maria.cocina`, citation key `mariacocina2026`): `citeSources` gives P-001 (the existing bibliography test shows the same); BibTeX gave `@misc{mariacocina2026, … author = {{@maria.cocina}}, url = {https://www.instagram.com/maria.cocina/p/abc/}`; RIS `ID - mariacocina2026`, `AU - @maria.cocina`; CSL-JSON `"citation-key": "mariacocina2026"`, `"literal": "@maria.cocina"`. In the open-format export the source's folder is `2026-03-14 P-001 - Cocinando hoy con P-001 [4bcp]` while `sources.bib`, `sources.csl.json`, the `.md` (its "Creators" and "Citation key" lines) and `source.json` inside that same folder all hold "maria". So the export pseudonymises a name in the folder and prints it in the files beside it. Direction: build reference-export items through `toCslItem` with `participantRules` (or the same coding and key rule), fail closed as the bibliography does; decide (owner) whether the open-format export's `.md`/`source.json` use the pseudonym map too.

**I3 — "No open copy", with no "Try again", after every offered file failed to download (a time-out, a 429, the network) — false, and permanent.**
`runner.ts:2156-2171`: a download that is refused or fails (`FetchFileError` for any reason, or the `TimedOut` of `FIND_DOWNLOAD_TIMEOUT_MS`) is a debug line and `continue`; when no offer gave a file (`:2202-2204`) the entry is written `no-open-copy` with the links and the reason DROPPED (`["nextTryAt","reason","offers"]`), even when `found.failed` had services that could not be reached. `retry` (`:2403-2410`) accepts `no-open-copy` only with `copy-some-unreachable`, so the row offers no "Try again" (the UI's own table `FindAcquire.test.tsx:2759`: phrase "No open copy", controls open/remove). A copy WAS found by the services; it could not be fetched this time. The test `runner.test.ts:3987-3998` pins exactly this outcome for a timed-out download. Under the loaded conditions the brief describes (and arXiv's 1-per-3-s politeness, a 503 from Europe PMC) a researcher meets a dead "No open copy" for works that are open. R282 e made the same distinction for the lookups ("a free copy may still exist", "Try again"); the download step was not covered. Direction: when offers existed and none could be downloaded, keep a reason of its own (or `copy-some-unreachable`) that says a copy was found but could not be fetched, and accept "Try again" (or retry like an unreachable lookup).

- **Fetchers:** one host rule on a parsed address (`fileHostAllowed`), redirects by hand (≤3, each re-checked), `identity` encoding only, `content-length` and streamed byte cap, exclusive `.part` 0600 in a checked non-symlink 0700 folder, type by the complete bytes (`%PDF-` + file-type; EPUB with `mimetype` first under R50 limits), part removed on every failure, no cookie/key/e-mail sent, messages without address or host (`fetch-file.ts`). - **The sealed queue:** sealed per line with purpose and project id as AAD; one scanner for reader and compaction; compaction checks its own output before the atomic replace; unreadable lines carried byte for byte; audit holds ids and counts only (`queue-store.ts`).
- **Citation sandbox:** worker per style, heap cap, start/render time-outs, worker killed on any failure, idle reaped, fresh engine state per render (`sandbox.ts`, `sandbox-worker.mjs`).
- **Open-format export:** decisions before any decryption; `deidentified-only` withholds; located media per the location rule; destination refused inside the library before and after creation and by real path; `.partial` then rename; held files and the find queue are not exported (only `sf.assets`).
