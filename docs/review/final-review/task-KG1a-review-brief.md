A caller that now throws in production is a Critical: prove or rule out each.
2. **The split into two changes** (the Find queue's repair of a torn last line, then the append; the watched-folder register the same): a crash between the two; a crash inside each; a second crash at the reopening; the torn line cut but the new line never added — is anything lost that the old single change kept (the entry's line, a "record-removed" line, a register line for a file already brought in — would a file then be brought in twice, or an origin lost)? Each is audited how — does the audit now show a "repair" change the researcher never asked for, and is its entry true and plain? Is the repair governed (can a project's rules refuse the repair and so block every later append; a read-only library; a locked project)? R505 b rules that a torn line is repaired BEFORE a larger change begins, never skipped: the implementer reports that a source deleted while the queue's last line is torn loses its "record-removed" line. Find every place where a line is added to a queue or register INSIDE a larger change (deleting a source, merging sources, moving a source to another project, attaching a found file, a watched file brought in), and say for each what happens now when the last line is torn — this list is what the fix round will build from.
