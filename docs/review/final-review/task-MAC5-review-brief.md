## The fault and the fix
The desktop app (Tauri 2; Rust shell in `apps/desktop/src-tauri`) crashed at start-up on macOS: `EXC_BAD_ACCESS at 0x30` on the queue `com.apple.WebKit.WebsiteDataStoreIO`, in `WTF::RunLoop::dispatch` ← `WebKit::WebsiteDataStore::fetchAllDataStoreIdentifiers`. Our caller: at every start the shell empties the sign-in window's data store unless "Stay signed in" is on (`shell.library.at_start(…)`, `src/lib.rs` about :154 → `src/library_window.rs` `at_start` about :1816 → the Mac `remove_data_stores` about :2197), BEFORE the service and the main window exist — so no web view had started WebKit and its class method handed its answer to a main run loop that did not exist. The ruling: `grep -n "Ruling R457" /home/user/AlexandrineOxiana/docs/handoff/LEDGER.md | cut -c1-6000`.

The fix (commit 1df473b; `git -C /home/user/AlexandrineOxiana/.claude/worktrees/ci-flake diff 35e6e35..1df473b`): a new `start_webkit(app)` — once, on the main thread through `app.run_on_main_thread`, it obtains `WKWebsiteDataStore::defaultDataStore(mtm)` and waits at most 10 s for that — called at the top of the Mac `remove_data_stores`; if it fails, WebKit is asked nothing and the emptying counts as failed.
