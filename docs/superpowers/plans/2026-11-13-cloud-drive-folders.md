# Cloud-Drive Watched Folders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** A researcher picks a Google Drive, OneDrive, Dropbox or ordinary folder on their Mac, chooses the project and collection it feeds, and every complete file put there is copied into the library by itself. The app never downloads a file the researcher did not ask for, and never changes the library because of what happened in the drive. A "Watched folders" screen shows each folder's state, and each source shows where it came from.
**Architecture:** The existing engine (`packages/library/src/import/watch.ts`) gains one named check, "is this file's content on this Mac?". It is made from `lstat` and, on macOS, the `SF_DATALESS` flag read by `/usr/bin/stat`. The check runs before any byte is read. A sealed, append-only register per watch in the project records which file became which source, so a later change, a removal or a move is shown on the source and never acted on. The folder is approved only through a new native-picker command in the shell. That command hands the service the path as a single-use grant on the shell's existing standard-input pipe, so the page never sends a path. The service exposes routes and a coalesced `watch.status` event, and the interface gains one screen and one notice on the source detail.
**Tech Stack:** chokidar 5.0.0 (existing, `packages/library/package.json:21`), Node 22 `fs.lstat` + `/usr/bin/stat -f` (macOS system tool, no new dependency), Tauri 2.12.5 + tauri-plugin-dialog 2.8.4 (existing, `apps/desktop/src-tauri/Cargo.toml:24-25`), Fastify (existing), React 19.3.1, Vitest 3.2.7, Playwright 1.63.0 (Chromium + WebKit). No new package anywhere.
**Spec:** docs/handoff/SPEC.md §5.4 "Watched folder (optional)" (lines 334-336), with the options it inherits: copy by default (line 322) and duplicates by identical hash (line 324); §4.5 "Cloud-synced folders and multiple devices" (lines 238-242: placeholders "detected and downloaded on demand, with a clear status"); §2.3 sync model (lines 86-92: out of scope, not blocked); §8A.1 tokens (563-568), §8A.4 accessibility (581-583); §9 "Originals never modified" (line 589).

## What exists today
- Engine: `watchFolder(deps, projectId, dir, options)` (`watch.ts:134`) uses chokidar with `awaitWriteFinish` of 2000 ms of unchanged size (`watch.ts:47-48, 286-295`) and `ignoreInitial: true`. A full scan runs at start (`watch.ts:350-360`), on the folder's return (`:325-336`) and on unlock (`:337-341`). The scan walks in name order and holds at most 100 files in the queue (`:244-261`). Subfolders are watched only with `options.recursive` (default false, `packages/core/src/model/project.ts:8-9`), to a depth of 20 (`watch.ts:51`).
- **It reads every file it sees.** `importOne` takes the SHA-256 of each file (`watch.ts:217`, `sha256Of` at `:124-128`) before anything else. `attach` then sniffs the type (`attach.ts:292`), hashes again (`:298`), reads the sidecars `.bib/.ris/.json/.opf` beside it (`attach.ts:253`, `sidecar.ts:40-50`), extracts metadata and copies the file. In a cloud folder the start-up scan would therefore download every online-only file. The library already has a placeholder test, `isPlaceholder` (`reconnect.ts:117-123`: `size > 0 && blocks === 0`, false on Windows), and `hydrate` (`reconnect.ts:131-147`), but the watch uses neither. ADR 0010 records that Node cannot read `st_flags` (`docs/adr/0010-reconnect-and-placeholders.md`, "Placeholders").
- A file still being written: events wait for 2000 ms of unchanged size (`watch.ts:292`). Scan-found files get no stability check at all (`:254`).
- Names skipped in silence: dotfiles and dot-folders, `~$`, `.part`, `.crdownload`, `.download`, `.tmp`, `thumbs.db`, `desktop.ini` (`watch.ts:98-111, 294`). `Icon\r`, macOS safe-save names (`*.sb-*`) and Google pointer files (`.gdoc` …) are not skipped. A pointer file reaches attach and fails with the misleading "This kind of file cannot be attached…" (`attach.ts:92`).
- A file changed after import: a `change` event re-imports it, and new content becomes **a new source** (`watch.ts:9-10, 302`; R81 minor, `LEDGER.md:203`).
- Renamed, moved or deleted files: nothing is recorded. A rename is re-hashed and skipped as a known hash (`watch.ts:218`). A deletion is ignored. A source the researcher deleted from the library is **imported again** at the next scan, because "known" means only the hashes of current sources (`watch.ts:168-180`).
- Duplicates: the same SHA-256 already in the project is skipped silently from a scan (`watch.ts:218`). From a new file, attach reports `duplicate` (`attach.ts:249-251`). A certain DOI or ISBN match is a duplicate, a fuzzy match goes to review (`attach.ts:253-256`, `packages/core/src/import/dedupe.ts:62`). One queue per project serialises every store (`attach.ts:309`, R81 I4).
- Where files land: the project, with no collection (attach has no collection option, `attach.ts:85`). Provenance is `manual_upload` with tool `"drag-and-drop"` (`attach.ts:259-264`). Nothing records which watch or which file a source came from, and provenance cannot be changed after creation (`packages/core/src/model/source.ts:25`).
- Copy or link: always a copy (`attach.ts:270`, `handling: "copy"`).
- Reporting: `WatchEvent`s (`watch.ts:65-72`; file names relative, never absolute) are published per file as `job.progress {kind:"watch"}` after path scrubbing (`apps/library-service/src/state.ts:855`). Nothing in the interface listens. There is no per-folder status, no count and no list of files that did not come in.
- Folder unavailable: polling at most every 10 s (`watch.ts:309-348`). A missing folder emits `stopped` with `WATCH_REASONS.removed`, and watching resumes when it is back, after the root is checked again (`:319-336`). Every error looks the same, so a privacy refusal (EPERM) cannot be told from a missing folder (`:264-272`).
- Approval and memory: `addWatchedFolder` checks that the folder is absolute, takes its real path, checks that it is a folder and that it neither is the library nor contains it (`watch.ts:486-492`). It writes `{id, options}` to project.json (governed and audited as `project.watched-folder.add`, `repo/import-settings.ts:51-58`) and the real path to `<appConfigDir>/watched-folders.json` per library, project and watch, mode 0600 in a 0700 folder, under the registry rule: missing means empty, a read error refuses, damaged content is set aside with a device notice (`watch.ts:377-541`; R78 c `LEDGER.md:200`; R69 `:185`). `approved-folders.ts` follows the same rule for Bulk Import (`approved-folders.ts:21-119`: absolute, stored as real path, per library, at most 1000).
- Routes: `GET`, `POST {dir, options}` and `DELETE /projects/:id/watched-folders[/:wid]` (`apps/library-service/src/routes/import.ts:175-206`). **The POST takes any absolute path the page sends** (`:186-187`). Watches start for every project when a library opens (`state.ts:828`) and are stopped and restarted with `startWatches`/`stopWatches` (`state.ts:861-888`). The engine stops by itself when the library closes or turns read-only, and pauses on a locked project (`watch.ts:165-166, 188-198`).
- No screen and no command: the ledger says "nothing lets a person set a watched folder up again — no screen and no command, only the service's routes" (`LEDGER.md:848`). The command-line tool has no watch command (`apps/cli/src`). The shell offers the page only `dialog:allow-open` and event listening (`apps/desktop/src-tauri/capabilities/main-window.json:7-11`, checked by `apps/desktop/scripts/launch-check.mjs:83-94`). `Info.plist` declares only App Transport Security (`apps/desktop/src-tauri/Info.plist`). The app is ad-hoc signed (`apps/desktop/scripts/build-macos.mjs:21`, R151). The service reads one token line from standard input and **discards anything after it, "never interpreted"** (`apps/library-service/src/startup-token.ts:153-172`).

## What a cloud-drive folder does differently
- **Online-only files are "dataless" and reading them downloads them.** Apple's guidance (TN3150, https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files; the page renders only with scripts, so its body could not be read here) is summarised at https://mjtsai.com/blog/2023/05/11/getting-ready-for-dataless-files: "avoid unnecessarily materializing dataless files", and "`stat` and `getattrlist` both trigger the materialization of any intermediate folders in the file's path, if they themselves are dataless". So stat does not download a file's content, but listing a folder can fetch that folder's listing (metadata, not files). → The plan reads no content before the check (W1, W2), and watches subfolders only when the researcher asks (the existing `recursive` default stays false).
- **The exact test is `SF_DATALESS` (0x40000000) in `st_flags`.** An Apple forum answer (https://developer.apple.com/forums/thread/808635) says "check the SF_DATALESS flag", and restic checks `unix.SF_DATALESS` on Darwin (https://remotebranch.eu/Stowage/restic/src/commit/1e6ed458ff1655706c388a95e1a9ef08a3912413/internal/fs/stat_darwin.go). Node 22 does not expose `st_flags` (ADR 0010). → W1 uses `size > 0 && blocks*512 < size` as a cheap first sign, and on macOS confirms with one `/usr/bin/stat -f "%i %Xf"` call per 200 suspects (mapped back by inode). If the tool fails, the answer is "unknown", which is handled as not downloaded (the safe side). It is not confirmed that File Provider reports `blocks === 0` for all three providers. One unverified user report says Google Drive does (claudeissues.com issue 40783, seen only in search results; the host could not be reached from here). This is the owner's first Mac check.
- **Google Drive** "Stream files" keeps files online unless they are made available offline, and on macOS 12.1+ uses File Provider under `~/Library/CloudStorage`. "Mirror files" downloads everything (https://support.google.com/drive/answer/13401938). Native Docs, Sheets and Slides appear as small pointer files (`.gdoc`, `.gsheet`, `.gslides` …). I found no source on how they behave under CloudStorage, so this is unconfirmed. → W1 names them and skips them with a sentence.
- **OneDrive** Files On-Demand is built on File Provider from macOS 12.1, cannot be turned off, and needs APFS (https://support.microsoft.com/en-us/onedrive/fix-onedrive-files-on-demand-issues-on-macos-12-1-or-later; https://techcommunity.microsoft.com/blog/onedriveblog/inside-the-new-files-on-demand-experience-on-macos/3058922). The folder is `~/Library/CloudStorage/OneDrive-<name>`, which `location.ts:64-71, 78-86` already recognises.
- **Dropbox** on File Provider lives in `~/Library/CloudStorage`. Files not marked "Available offline" can become online-only by themselves when the disk is low (https://help.dropbox.com/installs/macos-support-for-expected-changes, read through search results). Older set-ups keep `~/Dropbox` (`location.ts:89`). → A file that was local can become dataless later. W3 never reads a registered file that is not local, and shows "may have changed" instead.
- **Conflict copies** carry the editor's name, "conflicted copy" and a date in the name, e.g. "Report (Ana's conflicted copy 2026-11-13).pdf" (https://teamdynamix.umich.edu/TDClient/30/Portal/KB/ArticleDet?ID=11835; Dropbox's own page was not found). Other services add " (1)". → The name is never interpreted: the same content is a duplicate by SHA-256, and different content is a new source named as it is (W3).
- **Bursts and temporary names**: providers create files in bursts while they sync and write through hidden temporary files. → The skip list grows (W1), scan-found files get the same stability rule as events (W2), and the queue and status events are bounded (W2).
- **Privacy permission**: Apple lists `NSFileProviderDomainUsageDescription`, "A message that tells people why the app needs access to files managed by a file provider" (https://developer.apple.com/documentation/bundleresources/protected-resources). The TCC service is `kTCCServiceFileProviderDomain`, and Eclectic Light "has been unable to find any GUI control" for it (https://eclecticlight.co/2026/04/20/privacy-how-locations-are-protected/). A user report says that an app without the key is silently denied with no prompt, and that a terminal gets "Terminal would like to access files in Dropbox" (claudeissues.com issue 74658, search snippet only, unverified). A user report quotes '"FinderHelp.app" wants to access files managed by "Google Drive"' (https://discussions-jp-prz.apple.com/thread/254660914, search snippet). → W5 adds the key. W2 tells EPERM apart from "missing". Unconfirmed, and left to the owner's Mac: whether the prompt names the app for its child Node process (the "responsible process"), what a refusal does to `readdir` (EPERM is expected), how to undo a refusal with no Settings control, and whether every new ad-hoc-signed build is asked again.
- **The folder vanishing**: in Stream mode Google's app "must be open" to reach offline files (support page above). Signing out removes or empties the provider's folder (expected, unconfirmed). → W3 does not mark files gone when most of the register vanishes at once, and W2 reports "Cannot be reached" and picks the folder up again.
- **Names**: macOS keeps names as created, often NFD from cloud services, and compares them normalisation-insensitively. → Register keys are NFC (W1 `fileKey`), the name as on disk is kept for file access, and every name is shown through `UserText`.

## Global Constraints
- No cloud account, cloud API or new network host. Only the provider's local folder is read. Nothing is ever written, renamed, moved or deleted in a watched folder (the engine opens files read-only. W2 adds a test that the folder's tree, names, sizes and mtimes are unchanged after a run).
- **No content read before the check.** Every `open`/`read` of a file in a watched folder, including its sidecars and its hash, comes after `contentPresence` (W1) answered `"local"`, at most 2 s earlier. `"not-downloaded"` and `"unknown"` are never read, except when the researcher chose "Download and import them" (W4).
- Stability: a file is taken when two `lstat`s at least `WATCH_STABILITY_MS` = 2000 ms apart (R78 c) show equal `size`, `mtimeMs`, `ino` and `blocks`, its presence is `"local"`, and its name passes `nameRule`. Events and scans both use this rule.
- Skipped in silence: today's list (`watch.ts:98-111`) plus `Icon\r`, names ending in `.partial`, and names matching `/\.sb-[0-9a-f]{8}-[A-Za-z0-9]{6}$/`. Skipped and reported: `.gdoc .gsheet .gslides .gdraw .gform .gmap .gsite .gjam .gtable` with "This is a Google Docs, Sheets or Slides file. It lives only online, so there is nothing here to bring in."
- Duplicates: the engine's rule is unchanged. The same SHA-256 in the project means no new source, and a certain DOI or ISBN match too (`attach.ts:249-256`). The name is never compared.
- Copy only (SPEC line 322). Linking is not offered for a watched folder.
- Nothing in the library is deleted or replaced because of the drive. "Changed" means a different SHA-256 for the same register key. A changed file is never imported by itself. A source deleted in the library is not brought back for content the register already holds.
- Limits: `WATCH_RESCAN_MS` = 300000 (stat-only rescan), `WATCH_STATUS_INTERVAL_MS` = 1000 (at most one `watch.status` per folder per second), `WATCH_PROBLEMS_MAX` = 5000 file problems kept per watch, `WATCH_LOCAL_BATCH` = 200 paths per `/usr/bin/stat` call, `WATCH_FS_TIMEOUT_MS` = 30000 per folder operation, `WATCH_DOWNLOAD_CONFIRM_BYTES` = 1073741824, `FOLDER_GRANT_TTL_MS` = 600000, `FOLDER_GRANTS_MAX` = 20.
- R26: every library write (the register, a new version, a collection change) is one `runMutation` with a txn marker and an audit event carrying `details.txn`.
- R177 and R69: audit details hold ids, kinds and counts only. Never a file name, relative path or absolute path. The register holds relative names (sealed in encrypted projects). Absolute paths live only in device files (0600).
- R96: new routes are for the UI token only, loopback, errors with no absolute path. The one place a response may hold the chosen path is `place.display`, the researcher's own choice (R96 allows it).
- R113 and R145: colours from theme tokens (`lint:css`, `lint:colours`). Every file name, folder label and collection name goes through `UserText`. Never `innerHTML`. Every control can be reached by keyboard with visible focus. Dialog tests assert `document.activeElement` on open, Tab, Shift+Tab and close.
- Interfaces are declared once in `packages/shared/src/api/watched-folders.ts` and used by both sides.
- Wording: plain British English. Every quoted string below is exact. Numbers use the `toLocaleString("en-US")` style, as `MissingFiles.tsx:22` does. Sizes use the existing `formatSize` (`packages/ui/src/api/tools.ts`).
- Off-limits files (other lines of work): `packages/ui/src/reader/**`, `packages/ui/src/screens/Reader.tsx`, `packages/ui/src/routes/reader.tsx`, `packages/library/src/import/zotero-*.ts`, `apps/library-service/src/routes/zotero.ts`, `packages/library/src/repo/annotations.ts`. Files shared with them (`App.tsx`, `navigation.tsx`, `SourceDetail.tsx`, `e2e/fixtures.ts`, `state.ts`, `routes/import.ts`, `packages/shared/src/api/index.ts`) get only the lines named in each task, and the coordinator merges them.
- Commits end with the session's own trailers. No model identifiers anywhere else.

### Task W1: "Is this file's content on this Mac?" and the name rules
**Depends:** none **Can run beside:** everything. It creates one new file and touches nothing shared.
**Files:** Create: `packages/library/src/import/watch-local.ts` / Test: `packages/library/src/import/watch-local.test.ts`
**Interfaces:** Consumes: `classifyLocation`, `LocationEnv` (`location.ts:113, 21`); `ignoredName` (`watch.ts:99`). · Produces: `type ContentPresence = "local" | "not-downloaded" | "unknown"`; `contentPresence(paths: string[], opts?: { platform?: NodeJS.Platform; lstat?: (p: string) => Promise<Pick<Stats,"size"|"blocks"|"ino"|"isFile">>; datalessFlags?: (paths: string[]) => Promise<Map<string, boolean | null>> }): Promise<Map<string, ContentPresence>>`; `datalessFlagsDarwin(paths: string[]): Promise<Map<string, boolean | null>>` (`execFile("/usr/bin/stat", ["-f", "%i %Xf", "--", ...batch])`, no shell, batches of `WATCH_LOCAL_BATCH` = 200, matched by inode, `null` when unknown); `SF_DATALESS = 0x40000000`; `type NameRule = { skip: "silent" } | { skip: "report"; kind: "online-only-document"; reason: string } | null`; `nameRule(name: string): NameRule`; `POINTER_EXTENSIONS: readonly string[]`; `POINTER_REASON` (the sentence in Global Constraints); `type CloudProvider = "google-drive" | "onedrive" | "dropbox" | "icloud-drive" | "other-cloud"`; `cloudProviderOf(realPath: string, env: LocationEnv): CloudProvider | null`; `PROVIDER_NAMES: Record<CloudProvider, string>` ("Google Drive", "OneDrive", "Dropbox", "iCloud Drive", "the cloud drive"); `fileKey(rel: string): string` (NFC).
**Accept:**
1. `size === 0` → "local". `blocks*512 >= size` → "local" with no process started. Otherwise, on darwin, the flag decides: set → "not-downloaded", clear → "local" (an APFS-compressed file), `null` → "unknown". On linux, `blocks === 0 && size > 0` → "not-downloaded", otherwise "local". On win32 → "local" (W7 refuses cloud folders there).
2. No file is opened. A test with an `open` spy over 1,000 paths asserts zero opens, and that at most `ceil(suspects/200)` processes are started.
3. A path containing a newline, quotes or a leading "-" is passed safely (`--`, argv only), and a missing file maps to "unknown".
4. `nameRule` keeps every name `ignoredName` skips, adds `Icon\r`, `.partial` and `*.sb-xxxxxxxx-xxxxxx`, and reports the pointer extensions in any letter case. "Report (1).pdf" and "Report (Ana's conflicted copy 2026-11-13).pdf" → null.
5. `cloudProviderOf` maps `~/Library/CloudStorage/GoogleDrive-a@b.c/My Drive/x`, `OneDrive-Personal`, `Dropbox`, `~/Dropbox` and iCloud Drive as `location.ts` does, and a plain folder → null.
6. `fileKey("Ü.pdf" in NFD) === fileKey("Ü.pdf" in NFC)`.
**Tests first:** `watch-local.test.ts › "a file with all its blocks is local without starting a process"`, `"a dataless file on darwin is not-downloaded (flag set)"`, `"a compressed file on darwin is local (flag clear)"`, `"stat failing on darwin gives unknown"`, `"a sparse file on linux is not-downloaded"`, `"no file is opened for 1,000 paths"`, `"a name with a newline and a leading dash reaches stat safely"`, `"Google pointer files are reported with the sentence"`, `"Icon\\r and safe-save names are skipped silently"`, `"conflict-copy names are ordinary files"`, `"provider of each CloudStorage folder"`, `"NFD and NFC keys are equal"`. All fail first (the module does not exist).
**Verify:** `pnpm --filter @ao/library test -- watch-local && pnpm -r typecheck`
**Model:** Sonnet · **Review:** inode matching when `stat` prints errors for some paths, argv length at 200 long names (≤ 255 bytes each), that no `fs.open`, `readFile` or `createReadStream` exists in the module.
