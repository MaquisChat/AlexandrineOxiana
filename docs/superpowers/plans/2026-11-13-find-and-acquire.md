# Find and Acquire Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** The researcher types a reference (a title and author, or an author alone), one per line, into one box. Each line becomes a queue entry that completes the record, asks when several works or people fit, says "Already in your library" when it is, fetches a free legal copy, or (only on the researcher's press) fetches the file through the library's sign-in in a separate window, with their browser and the extension as the fallback. Otherwise the record comes in without a file and the entry says where the work can be had.
**Architecture:** A new library module `packages/library/src/find/` holds four parts. The queue is an append-only, sealed and governed file per project. The runner moves entries between states, a few at a time and politely. The searches add ranked candidates, people and works, and Elicit to the existing lookup client. The free-copy fetcher takes files only from a fixed list of hosts and checks each file against its record. The service exposes the queue and two device settings (`search-sources.json`, `your-library.json`). The desktop shell gains a sign-in window with its own cookie store and no IPC. When that window reaches a PDF, the shell fetches the file itself and hands it to the service as a second line shape on the existing standard-input pipe. The extension gains one action on its existing token.
**Tech Stack:** undici 8.12.3 (`packages/library/package.json:27`; MockAgent in tests), file-type 22.2.0 (`:23`), pdfjs-dist 6.4.299 (`:25`, the existing extractor), @napi-rs/keyring (existing `secrets.ts`), Fastify 5.12.7, React 19.3.1, msw 2.15.0, Vitest 3.2.7, @playwright/test 1.63.0; Tauri 2.12.5, tauri-runtime-wry 2.12.3, wry 0.57.2, objc2-web-kit 0.3.2 (`apps/desktop/src-tauri/Cargo.toml:24`, `Cargo.lock:3471, 3685, 4718, 2323`). **One new dependency (F16):** `reqwest = { version = "=0.13.5", default-features = false, features = ["native-tls", "system-proxy", "stream"] }`. Its licence is MIT OR Apache-2.0. It is already in `Cargo.lock:2790` without TLS. `native-tls` uses Security.framework on macOS and OpenSSL 3 (Apache-2.0) on Linux. The default `rustls` feature is NOT used: it brings aws-lc-rs, which is partly under the OpenSSL/SSLeay licence, and that licence is incompatible with AGPL-3.0-or-later (R218).
**Spec:** docs/superpowers/specs/2026-11-13-find-and-acquire-design.md (whole). docs/handoff/SPEC.md §3.2 provenance (line 113), §3.3 assets (lines 117–123), §5.1 "Legitimate access chain" (line 265), "Out of scope … shadow libraries" (line 268, and 648, 678), §6.1 single policy checkpoint and fail closed (lines 467–475).

## What exists today
- **Lookup client.** `HttpClient` (`lookup/http.ts:112`) does GET only. Rates per host: Crossref 5/s, OpenAlex 5/s, Open Library and LoC 1/s, any other host 1/s (`:34-42`). It retries 3 times with back-off (`:276-295`). A JSON body is at most 5 MB (`:47`). Redirects are followed at most 3 times and only within the same origin (`:48`, `:320-321`). There is a disk cache with a 30-day TTL, kept in memory only for sensitive (encrypted) projects (`:165-191`). A contact e-mail can go in the User-Agent for every host (`:131-132`), but the service never passes one (`apps/library-service/src/state.ts:602`). Test mode uses recorded answers for exact GET URLs, under `NODE_ENV=test` only (`recorded.ts:380-408`).
- **Lookups** are governed per provider: `evaluate({action:"process", process:{op:"metadata_lookup", provider}})`, and a deny is a debug note (`lookup/context.ts:45-63`). `searchTitle` asks OpenAlex for 5 results (`lookup/index.ts:153-156`, `openalex.ts:224-234`). Only imports call it (`import/resolve.ts:312`, `import/attach.ts:212`, `bulk/run.ts:652`). There is no Crossref search, no people search and no free-copy lookup.
- **Confidence.** `scoreConfidence` gives a title match 0.5 + 0.3·sim when sim ≥ 0.9 (`core/src/import/confidence.ts:28-32`). `AUTO_ACCEPT_THRESHOLD` is 0.9 (`core/src/model/import-batch.ts:8`). `titleSimilarity` is a Dice coefficient over token sets (`core/src/verify/evidence.ts:60-67`).
- **The capture queue is memory only.** It is not library data, and a restart forgets it (`library/src/capture/queues.ts:1-5`). So the design's "library data in the project (like the capture queue)" has no precedent there. The persistent precedent is the watched-folder register. It is append-only JSONL, sealed per line in encrypted projects and 0600 otherwise. Each append is one `runMutation` with the policy `store {identifiable:false, hasLocation:false}`, a txn marker, and an audit of counts only. A torn last line is repaired (`repo/watch-register.ts:1-19, 65, 246-311`).
- **Duplicates.** `findDuplicate` treats the same DOI or ISBN as certain, and title + first family + year (±1, sim ≥ 0.92) as likely (`core/src/import/dedupe.ts:20, 49-84`). The index answers `findSourceBy({doi}|{isbn}|{sha256})` across every indexed project, with `project_id` on each row (`index/db.ts:539, 573`). Encrypted projects are in the index only while unlocked (R30). Bulk import buckets fuzzy keys (`import/bulk/dedupe.ts:26-60`).
- **Attach.** `attachFiles(projectId, paths, {toSourceId})` adds originals with capture method `manual_upload` (`import/attach.ts:82-112`). `addCapturedOriginal(repo, projectId, sourceId, input, captureMethod)` evaluates capture and store for any method (`repo/repo.ts:975-990`). Provenance is per source and immutable. It already has `access: "signed-in-session" | "public"` (`core/src/model/source.ts:26-46`). An asset carries no provenance of its own (`core/src/model/asset.ts:4-50`).
- **Review queue.** `review/pending.jsonl` is sealed in encrypted projects. Its entries have `kind: "verification" | "import"`, `cause`, `reasons`, `candidates` and `duplicateOf` (`repo/review.ts:15-62, 297-372`). There is no entry kind for "a file that does not match its record", and no place for a held file.
- **Governance.** `captureMethods` is a list, and arrays REPLACE the defaults when a project's file names the key (`core/src/governance/schema.ts:109, 199, 238-245` deepMerge). The engine refuses a method that is not in the list (`engine.ts:166`). The CLI always writes `captureMethods` when a method is chosen (`apps/cli/src/commands/project.ts:26-27`), and so does the Governance screen when a box is ticked (`ui/src/screens/GovernanceSettings.tsx:507-516`). **So any project whose rules were ever opened up for browser capture or the downloader would NOT get a new method added to the defaults.** In profile merging, booleans treat `true` as stricter (`merge.ts:94-99`). Metadata providers outside `PUBLIC_METADATA_SERVICES` need a declared vendor, which profiles filter by DPA or BAA (`schema.ts:33, 286-291`; `merge.ts:178-192`).
- **Secrets.** `SECRET_NAMES = ["zotero-api-key"]` (`library/src/secrets.ts:20`). The routes `GET/PUT/DELETE /secrets/zotero-api-key` are UI only (`routes/zotero.ts:148-178`). `ZoteroKeyField` is Zotero Task Z9 and is not built yet.
- **Extension.** The service lets the extension token reach only `POST /capture/browser`, `POST /capture/browser/links` and `GET /projects` (`apps/library-service/src/server.ts:102-107, 249-252`). The paired origin is required on POSTs. Bodies are capped at 32 MB for browser capture (`routes/capture.ts:77, 389`). The manifest grants `activeTab`, `scripting` and `storage`, and host permissions on loopback only (`apps/browser-extension/manifest.json`).
- **Shell.** There is one window, `main` (`src-tauri/src/lib.rs:163-169`), with `on_navigation` limited to the app origin and `on_new_window` → Deny. The app quits when the last window closes (`lib.rs:330-357`). There is one app command, `pick_watch_folder`, granted to `main` only (`lib.rs:238, 312`; `capabilities/main-window.json`). Remote origins are refused every app command unless a `remote` capability names them (`tauri-2.12.5/src/webview/mod.rs:2075-2081`). The grant line is `{"type":"folder-grant","id","path"}` (`grant.rs:55-71`). The service accepts exactly that one shape after the token (`startup-token.ts:14-20`, `folder-grants.ts:46`; R207). The launch check's `EXPECTED_IPC` covers the main window only (`apps/desktop/scripts/launch-check.mjs:84-107`). The minimum macOS is 15.0 (`tauri.macos.conf.json`). Nothing opens a link in the researcher's browser.
- **wry 0.57.2 on macOS, read in the crate.** `data_store_identifier` uses `WKWebsiteDataStore.dataStoreForIdentifier` on macOS 14+, and falls back to the default store otherwise (`wkwebview/mod.rs:265-290`). `AppHandle::remove_data_store` and `fetch_data_store_identifiers` exist on Apple platforms and must run on the main thread (`tauri-2.12.5/src/app.rs:433, 456`). `cookies()` returns every cookie of the window's store, HttpOnly included. **`cookies_for_url` matches the cookie domain exactly and ignores the path** (`wkwebview/mod.rs:1270-1292`), so the domain cookies that host-rewriting proxies set would be missed. The navigation policy hands only a URL string, for every frame, and no MIME type (`wkwebview/navigation.rs:64-100`). There is no API that reads a response's type. `on_page_load` and `on_document_title_changed` exist (`webview/webview_window.rs:326, 421`).

## Global Constraints
- **No shadow libraries.** Files come only from `FREE_COPY_FILE_HOSTS` (below) or, through the library, from the address the sign-in window itself reached. No setting, response or test switch outside `NODE_ENV=test` adds a host. A response never decides a host: an open-access address on any other host becomes a link under "Where to get it" ("A free copy may be at <host>").
- **Hosts, https on port 443 only.** Metadata: `api.crossref.org`, `api.openalex.org`, `openlibrary.org`, the LoC hosts as today, `elicit.com` (path `/api/v2/search/papers` only). Free-copy lookups: `api.unpaywall.org`, `export.arxiv.org`, `www.ebi.ac.uk` (path prefix `/europepmc/webservices/rest/`), `api.semanticscholar.org`, `directory.doabooks.org`, `archive.org`. `FREE_COPY_FILE_HOSTS`: `arxiv.org`, `export.arxiv.org`, `europepmc.org`, `pmc.ncbi.nlm.nih.gov`, `www.ncbi.nlm.nih.gov`, `library.oapen.org`, `directory.doabooks.org`, `archive.org`, and hosts matching `^ia\d{3,6}\.us\.archive\.org$`. A redirect is followed (at most 3) only to a host in the same set. OpenAlex's cached copies (`content_urls`) are not used: their terms could not be verified.
- **Rates.** Crossref 5/s with one request at a time (public pool: rate 5, concurrency 1; crossref.org "Access and authentication"). OpenAlex 5/s. arXiv one request every 3 s, one connection (info.arxiv.org/help/api/tou.html). Semantic Scholar 1/s. Unpaywall, Europe PMC, DOAB and the Internet Archive 1/s. Elicit 1 per 2 s; a 429 blocks the IP for 5 minutes (docs.elicit.com), so a 429 stops Elicit for 300 s. File downloads: at most 1 at a time per host, and 2 at a time overall. The runner works on at most 2 entries at once per open library.
- **OpenAlex's budget** (help.openalex.org rate-limits; example-costs): a search (`search=`) costs $1 per 1,000 calls, a list or filter $0.10 per 1,000, and a single work by id is free. Without a key the budget is $0.10 a day, about 100 searches. With a free key it is $1. A 429 whose body or `X-RateLimit-Remaining: 0` shows the daily budget pauses OpenAlex searches until `X-RateLimit-Reset`, or 00:00 UTC when that header is absent. Entries go on with Crossref alone and say "OpenAlex's free daily allowance is used up; searching Crossref only until tomorrow." The optional key is the secret `openalex-api-key`, sent as `Authorization: Bearer`.
- **What is sent.** A public service receives the words typed, an identifier, or a title and first author built from a chosen record. Nothing else. The User-Agent is `USER_AGENT` without `mailto`. The researcher's e-mail goes to Crossref only if typed into Crossref's setting, and to Unpaywall (as `email=`) only if typed into Unpaywall's. It is never cached, logged, audited or written to a library. Tests use `test-only@example.invalid`, and no real address appears in the repository.
- **Limits.** A typed line is 2–500 characters. One "Add" holds at most 50 lines. Each project has at most `FIND_QUEUE_MAX` = 500 entries not removed ("The queue holds 500 entries. Remove some finished ones first."). Candidates kept per entry: 10 works, 20 people, and 200 works of a person (two pages of 100). One tick adds at most 50 works. Strings kept: title ≤ 1,000 characters, a name ≤ 200, at most 100 creators. A queue line is ≤ 64 KiB. A free-copy file is ≤ 100 MB and a library file ≤ 200 MB. A download may take 180 s overall, and its headers 30 s.
- **A "PDF" is a PDF.** The first 1,024 bytes hold `%PDF-` and `file-type` says `application/pdf`. An EPUB is a ZIP whose first entry is `mimetype` = `application/epub+zip`, under the R50 zip limits. Anything else is refused: "The service sent something that is not a PDF or EPUB."
- **Sure enough to complete without asking** (`decideMatch`, F2). Tokens are `normalizeTitle` words. A candidate is *sure* only when all of the following hold:
  1. At least 90% of its title tokens are in the typed tokens (`titleCover ≥ 0.9`).
  2. At least one of its creators' family names is a typed token.
  3. At most 1 typed token is left unexplained by title, creator names, a 4-digit year or the words {and, et, al, by, the, of, in}.
  4. A typed year, if any, is within ±1 of its year.
  5. No other candidate has `titleSimilarity` ≥ 0.8 to it with a different DOI or ISBN (other editions or translations).
  6. The next best candidate's score is at least 0.2 lower. Score = 0.6·titleCover + 0.3·(creator matched) + 0.1·(year matched or none typed).

  Otherwise the entry is "Choose" when a candidate scores ≥ 0.4, and "Not found" when none does. Elicit candidates never make an entry sure on their own: they are always offered as choices.
- **Person** (`decidePerson`, F8). An author alone is recognised when, of up to 20 people from OpenAlex `authors?search=`, the best one's `display_name` tokens cover every typed token, and no work candidate has `titleCover ≥ 0.6`. With exactly 1 such person, the state goes to "Choose works". With more, it goes to "Choose the person".
- **Already in your library.** A certain match is the same DOI or ISBN through `findSourceBy`. A likely match is the fuzzy rule of `dedupe.ts`. Off: only sources whose `project_id` is the entry's project count. On ("Check everything I have"): every project of the open library that is unlocked counts. The entry stores `elsewhere: true` and nothing else about another project. Where it is is worked out again at request time and never written. Locked projects are counted: "2 locked projects were not checked".
- **R26 and audit (R177).** Every queue write is one `runMutation`. The ops are `project.find.add`, `project.find.update`, `project.find.remove` and `project.find.compact`. Each audit entry holds the entry ids, counts by state, counts of lines, and nothing else: no typed text, title, name, host, URL or key. Record creation is audited as today's `source.create`. Files go through `addCapturedOriginal`.
- **Running.** Nothing runs for a locked project, a read-only library or a project whose rules refuse the step. Lookups and free copies run by themselves. A library fetch runs only after the researcher's press on that entry: one entry at a time, at least `LIBRARY_PAUSE_MS` = 20,000 between one hand-over and the next start, and never resumed at start-up.
- **Secrets.** `elicit-api-key` and `openalex-api-key` sit beside `zotero-api-key` in the keychain only. The cookies of the sign-in window never leave the shell's process. No key or cookie appears in a library, a log (REDACT already covers `cookie`, `server.ts:112`), an audit entry, an error, a URL or a test fixture.
- **Words.** Plain British English. Every state is written out in words. Outside text (typed lines, titles, names, affiliations, venues, hosts) is shown only through `UserText`. The refusal states its cause: "This project's rules do not allow …" (governance) or "Switched off in Search sources" (settings).
- **UI (R113, R145).** Colours come from theme tokens only, with no new token. No `innerHTML`. Everything works by keyboard and is named for screen readers. Dialog tests assert `document.activeElement` on open, during Tab and Shift+Tab, and after close.
- **Shared types** are declared once, in `packages/shared/src/api/find.ts` and `search-settings.ts`.
- **Tests never touch the network.** Unit tests use undici MockAgent with `disableNetConnect`. End-to-end tests use `AO_FIND_STANDIN=http://127.0.0.1:<port>`, honoured only under `NODE_ENV=test` and only in that exact form (otherwise the service refuses to start, naming the variable). It routes every request made by `find/` to the stand-in, with header `x-ao-standin-host: <original host>`. The desktop scenario uses a local stand-in library proxy and publisher.
- **Off-limits for this plan:** `packages/ui/src/reader/**`, `screens/Reader.tsx`, `routes/reader.tsx`, `screens/Library.tsx`, `components/SourceTable.tsx`, `theme/tokens.css`, `import/zotero-*.ts`, `import/bulk/*`, `routes/zotero.ts`, `import/watch*.ts`, `repo/watch-register.ts`, `routes/watched-folders.ts`, `grant.rs`, and `folder-grants.ts` except the one dispatch line F17 names.

Pinned in F2 by `search.test.ts › "two editions of Distinction with different ISBNs are never sure: the entry is Choose"` and `"a preprint and its article with different DOIs are offered both"`.
2. **A service answers with a different paper's PDF**, or with an HTML page called .pdf. Pinned in F11 by `file-check.test.ts › "a PDF whose text names another DOI goes to the review queue, never into the source"` and in F10 by `fetch-file.test.ts › "an HTML page served as application/pdf is refused as not a PDF"`.
3. **A common name with forty people** ("J. Smith"). There must be no silent choice, and the list must stay bounded. Pinned in F8 by `people.test.ts › "forty people named Smith: Choose the person lists 20, says more exist, and nothing is added"`.
4. **The same reference typed twice at once**, in one Add or in two quick Adds. The result must be one source and one "Already in your library", never two sources. Pinned in F4 by `runner.test.ts › "two entries for one DOI, run together, create one source; the other says Already in your library"`.
5. **The sign-in window led to a hostile or unexpected host, or to an SSO address that a replayed GET would spoil.** The shell never fetches a sign-in address. Cookies go only to their own domain. Whatever arrives is checked. Pinned in F16 by `library_window::tests::cookies_for_hostile_host_carry_only_its_own`, `never_fetches_saml_or_login_paths`, and by the F19 scenario "a publisher redirecting to another host hands over no file without the check".
6. **The laptop lid closed in the middle of a fetch, or the app quit during one.** No half file is left in a source, the entry returns to a stable state, and a library fetch never restarts by itself. Pinned in F4 by `runner.test.ts › "a crash during Fetching resumes as Looking for a copy; a library entry resumes as No open copy"`, and in F10 by `"a download stalled past 180 s is dropped and its .part file removed"`.
7. **A match only in a locked project, or with "Check everything I have" on beside an encrypted project.** Nothing of the other project may be written here. Pinned in F4 by `"a match in another unlocked project stores only elsewhere: true; the queue file and audit hold no id or title from it"`.

### Task F1: Three new ways of acquiring in the governance model
**Slice:** 1 **Depends:** ruling 2 **Can run beside:** F2, F3 (core only; no shared file)
**Files:** Modify: `packages/core/src/model/source.ts`, `packages/core/src/governance/schema.ts`, `engine.ts`, `merge.ts`, `packages/ui/src/screens/governanceModel.ts` (labels and defaults only) / Test: `engine.test.ts`, `merge.test.ts`, `loosen.test.ts`, `profiles.test.ts`
**Interfaces:** Produces: `Provenance.captureMethod` gains `"reference_lookup" | "free_copy" | "library_access"`; `ACQUIRE_METHODS = ["reference_lookup", "free_copy", "library_access"] as const`; `CAPTURE_METHODS` = the provenance options minus `ACQUIRE_METHODS`; `GovernanceConfig.acquireMethods: AcquireMethod[]`, default all three; the engine's `capture` checks `acquireMethods` for these three and `captureMethods` for the rest; `loosenedControls` reports `acquireMethods` when one is added; `ACQUIRE_LABEL` in `governanceModel.ts`: "Find and acquire: records completed from a reference you type", "Free legal copies (arXiv, Europe PMC, Semantic Scholar, open-access books, the Internet Archive, Unpaywall)", "Through your library's sign-in".
**Accept:**
1. A project whose `governance.yaml` has no `acquireMethods` key allows all three. This is every existing project, including one with an explicit `captureMethods` list.
2. `acquireMethods: []` refuses each one, with reason "Capture method free_copy is not enabled for this project" (the engine's existing sentence).
3. No profile changes the default (the owner's decision 1). A profile minimum can list them only if a later ruling says so.
4. `acquireMethods: [free_copy]` in `captureMethods` is a schema error. The reverse is an error too.
5. Elicit is NOT a capture method. It is the provider `elicit` under `processing.metadata_lookup`. It needs `vendors: [{id: elicit, …}]` (and `dpa: true` under GDPR, `baa: true` under HIPAA, as today). It is not added to `PUBLIC_METADATA_SERVICES`.
**Tests first:** `engine.test.ts › "an old rules file with an explicit captureMethods list still allows free_copy"`, `"acquireMethods: [] refuses all three"`, `"elicit is refused until processing.metadata_lookup names it and a vendor is declared"`; `loosen.test.ts › "adding library_access is loosening; removing it is not"`; `merge.test.ts › "GDPR drops elicit without a DPA"`. All fail first.
**Verify:** `pnpm exec vitest run packages/core/src/governance` then `pnpm -r typecheck`
**Model:** Sonnet · **Review:** an older rules file must not be read as refusing; it must be impossible to allow a free copy by writing it into `captureMethods`; the immutability of provenance is untouched.

**Files:** Create: `apps/browser-extension/src/find.ts` / Modify: `apps/library-service/src/server.ts` (`EXTENSION_ROUTES` gains `"GET /find/waiting"` and `"POST /find/waiting/:ticket/file"`; both need the paired Origin), `routes/your-library.ts`, `apps/browser-extension/src/popup/Popup.tsx`, `background.ts`, `api.ts`, `types.ts`, `e2e/stub-service.ts` / Test: `find.test.ts`, `Popup.test.tsx`, `apps/library-service/src/find-extension.test.ts`, `apps/browser-extension/e2e/find.spec.ts`
**Interfaces:** Produces:
- `GET /find/waiting` → `{ waiting: Array<{ ticket: string; label: string }> }`. The label is a title of at most 200 characters, shown with `textContent` in the popup. At most 20 are returned, only entries "waiting-browser" whose project is unlocked, and the extension receives no project id.
- `POST /find/waiting/:ticket/file`: body `application/pdf` (a content-type parser for that type on this route only, ≤ 200 MB), header `x-ao-page: <the page address>` (≤ 2,048 characters, scrubbed before use).
- Entry state "waiting-browser" ("Waiting for you in your browser").
- `waitingForFile(api): Promise<…>`, and `sendPdf(api, ticket, tabId): Promise<{ ok: boolean; sentence: string }>`. The PDF is read by a script injected on the researcher's click into the active tab with `scripting.executeScript`. It does `fetch(location.href, { credentials: "include" })` in the page's own origin, and only when `document.contentType === "application/pdf"` or the URL is in the waiting entry's host. No new permission is added.
**Accept:**
1. The popup shows "Add this PDF to Find and acquire" only when the app has a waiting entry. With several, it shows a list to choose from.
2. The results are "Added to Find and acquire" and "This page is not a PDF".
3. The file then follows F17's path with `via: "browser-extension"`.
4. Rate: one POST at a time per extension token.
**Tests first:** `find-extension.test.ts › "the extension cannot list the queue or projects through find"`, `"a ticket that is not waiting-browser is 404"`, `"a non-PDF body is refused"`; `find.test.ts › "no new permission in the manifest"`; `Popup.test.tsx › "the button shows only with a waiting entry; labels via textContent"`; `e2e/find.spec.ts › "a PDF tab is sent to the waiting entry"`. All fail first.
**Verify:** `pnpm --filter @ao/library-service exec vitest run src/find-extension.test.ts && pnpm --filter @ao/browser-extension test && pnpm --filter @ao/browser-extension run e2e`
**Model:** Sonnet · **Review:** the extension's reach (R110, R111, R116); a page posing as a PDF; whether Chrome's PDF viewer lets the injected script run (listed for the owner).

## Rulings the coordinator must make before work starts
1. **A second line shape on the shell's pipe.** Recommended: yes. The shape is exactly `{"type":"file-grant","id":"<32 hex>","ticket":"<32 hex>","path":"<absolute>"}`, for a file the shell wrote under `<AO_CONFIG_DIR>/library-inbox/`. This changes R98/R155 (as changed by R207) for this one more shape and nothing else, and the service checks the path's real parent. Cost if wrong: the alternative routes the cookies or the bytes through the page or the service. The page would see a signed-in session's file without the shell's checks, or the service would hold library cookies, which the design forbids.
2. **How projects allow the three new ways.** Recommended: a separate list `acquireMethods` (default `[reference_lookup, free_copy, library_access]`), because `captureMethods` replaces its default whenever a project names it (`schema.ts:238-245`; written by the CLI `project.ts:26-27` and the Governance screen `GovernanceSettings.tsx:507-516`). Adding the methods there would leave every project already opened up for the browser refusing free copies. Also: a third method, `reference_lookup`, for the record made from a typed reference, because provenance needs an honest method. Elicit stays a `metadata_lookup` provider that needs a declared vendor. Cost if wrong: either existing projects silently refuse, or a record carries a false capture method.
3. **Where the queue lives.** Recommended: `<Project>/find/queue.jsonl`, governed and sealed like the watch register. The capture queue the design names as the model is memory only (`capture/queues.ts:1-5`). In a project that is not encrypted, the typed lines and candidates sit in plain text (0600), like `batch.json` locations (R69). Flag them for the pseudonymisation review (R64). Cost if wrong: in a device file the queue would not follow the library to another Mac, and would sit outside governance.
4. **Free copies only from a fixed list of file hosts; every other open-access address becomes a link.** Recommended: yes. OpenAlex, Unpaywall and Semantic Scholar point to thousands of repositories, so many legal copies will be links rather than fetched files. Cost if wrong: either a response decides the host (contrary to the design), or the list grows by code change as real cases appear.
5. **OpenAlex's new budget.** Recommended: an optional OpenAlex key in Search sources (keychain), and Crossref alone when the daily allowance is spent. Cost if wrong: without a key about 100 searches a day; an author's works and many references a day will stall.
6. **Each file records how it was got.** Recommended: `Asset.acquired`, set once when the asset is added, because the source's provenance is immutable and was written when the record came in. Cost if wrong: provenance would be unable to say which service or route a file came from.
7. **One new Rust dependency** for the shell's own fetch: `reqwest =0.13.5` with `native-tls`, not its default rustls/aws-lc-rs (licence, R218). Cost if wrong: an AGPL-incompatible crypto library shipped, or a hand-written HTTP client.
8. **How the shell decides it has reached a PDF.** Recommended: address patterns plus the researcher's "Add the PDF showing in the sign-in window", and never a GET to a sign-in address. The web view tells the shell only addresses, never types (`wry navigation.rs:64-100`). Cost if wrong: probing every page would replay single-use sign-in addresses and break sign-in.
9. **A mismatched file is held in the project** (`find/held/<entryId>.<ext>`, encrypted where the project is), with a new review cause and the decisions "Use this file" and "Not this file". Cost if wrong: the file is lost, or it goes into the source unchecked.
